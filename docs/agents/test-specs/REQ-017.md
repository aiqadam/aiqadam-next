# REQ-017 — Verification spec: public event card and `/events` upcoming list

**Scope test:** Step 2's `artifacts_out` (`apps/bot/src/domain/event.ts` extended,
`apps/bot/src/i18n/formatTimeInTimezone.ts` new, `apps/bot/src/handlers/{event,start}.ts`,
`apps/bot/src/i18n/{types,ru,en}.ts` new `events.*` keys, `apps/bot/src/index.ts`) is real
user-visible/behavioral surface — a live Telegram bot process renders a real event card
(map links, chapter-local times, agenda, seats/waitlist) and a real `/events` list against
real `events`/`venues`/`chapters`/`registrations` rows. Full Steps 3b/4 apply.

**Independence note.** BACKEND-DEV already wrote `apps/bot/src/domain/event.test.ts`
(pure-function unit tests for `computeSeatsLeft`/`isRegistrationOpen`/`isFinished`/
`buildSeatsLine`/`buildEventCardContent`) and `apps/bot/src/i18n/formatTimeInTimezone.test.ts`
(the TZ-independence property). Those are real, already-passing, and this spec does not
duplicate them wholesale — TEST-RUNNER is told exactly which existing tests to re-run as
part of AC2/AC3/AC5 below. What this spec adds, and what constitutes the actual
independent re-derivation, is coverage of the parts **no unit test exercises at all**:
the two new DB-integration queries (`getEventByIdWithChapterTimezone`,
`listUpcomingPublishedEvents`), the `/events` handler's own composition, the deep-link
handler's `isFinished` gating against a live database, cover-photo vs. plain-text branch
selection, `/events` command registration, and i18n catalog parity — none of which a pure
unit test over already-fetched objects can catch (e.g. a wrong JOIN condition, a filter
that silently drops or leaks a row, a catalog key present in `types.ts` but missing from
`ru.ts`/`en.ts`, or `/events` never actually wired into `index.ts`).

**Harness note (read before running any case):** reuses REQ-013/014/015/016's established
grammY-dispatch method — a real `grammy.Bot` built with a dummy token + manually-supplied
`botInfo`, `bot.api.config.use()` intercepting outbound calls, `bot.handleUpdate()`
dispatching synthetic `Update` objects through the real command matchers, against the real
fixture Postgres from `apps/bot/docker-compose.yml`. Not committed as reusable
infrastructure — the harness script is written, run, then deleted at the end of the run.

**`tg_id` range:** `1000000000`+ — distinct from REQ-013/014/015/016's ranges, so all
specs can run against the same scratch DB without collision.

## Shared setup (run once before AC1–AC6)

1. `cd apps/bot && docker compose up -d` — starts the throwaway Postgres (host port
   `55432`, user/password/db all `bot`).
2. Poll until ready: `docker compose exec postgres pg_isready -U bot` reports
   `accepting connections` (poll every 2s; do not sleep-guess).
3. `export DATABASE_URL=postgres://bot:bot@localhost:55432/bot` (PowerShell:
   `$env:DATABASE_URL = "postgres://bot:bot@localhost:55432/bot"`).
4. From `apps/bot`: `npx drizzle-kit migrate` — applies every migration through REQ-016's
   `users.pending_source` addition (REQ-017 adds no migration — confirm
   `git diff master...HEAD -- apps/bot/src/db` is empty before proceeding; if it is not,
   STOP and report a design/AC10 discrepancy).
5. Seed fixture rows via `psql "$DATABASE_URL" -c "<statement>"` — exact statements given
   per case.
6. Write the harness script `apps/bot/scratch-verify-req017.ts` (NOT committed — delete at
   the end of the run):

```ts
import { Bot } from "grammy";
import { makeEventsListHandler } from "./src/handlers/event.js";
import { makeStartHandler, makeConsentCallbackHandler } from "./src/handlers/start.js";
import { createDbClient } from "./src/db/client.js";

const { db } = createDbClient(process.env.DATABASE_URL!);

const bot = new Bot("000000:DUMMY_TOKEN_NOT_REAL", {
  botInfo: {
    id: 1,
    is_bot: true,
    first_name: "Test",
    username: "test_bot",
    can_join_groups: true,
    can_read_all_group_messages: false,
    supports_inline_queries: false,
  },
});

const captured: Array<{ method: string; payload: unknown }> = [];
bot.api.config.use(async (_prev, method, payload) => {
  captured.push({ method, payload });
  return { ok: true, result: true } as never;
});

bot.command("events", makeEventsListHandler(db));
bot.command("start", makeStartHandler(db));
bot.callbackQuery(/^consent:agree(?::.+)?$/, makeConsentCallbackHandler(db));

function messageUpdate(updateId: number, tgId: number, text: string) {
  const firstLine = text.split("\n")[0];
  const cmd = firstLine.split(" ")[0];
  return {
    update_id: updateId,
    message: {
      message_id: updateId,
      date: Math.floor(Date.now() / 1000),
      chat: { id: tgId, type: "private" as const },
      from: { id: tgId, is_bot: false, first_name: "Test" },
      text,
      entities: [{ type: "bot_command" as const, offset: 0, length: cmd.length }],
    },
  };
}

async function main() {
  await bot.init();
  // --- dispatch calls inserted per-case below, in order ---
  console.log(JSON.stringify(captured, null, 2));
  process.exit(0);
}

main();
```

**Teardown (after ALL cases are done):** delete `apps/bot/scratch-verify-req017.ts`,
