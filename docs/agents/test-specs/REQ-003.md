# Test Spec — REQ-003 (Add `en` locale to the i18n mechanism)

Source requirement (from handoff `handoffs/WF02-REQ003-REQ004/step-03-test-designer.json`
`context.requirement_text.REQ-003`):

> Add `'en'` to `src/i18n/routing.ts`'s locales array (now `["ru","uz","en"]`),
> `defaultLocale` stays `"ru"`. Create `messages/en.json` matching `messages/ru.json`'s
> 177-leaf-key structure, every value duplicated verbatim from `ru.json` as a placeholder
> except `Metadata.ogLocale = "en_US"`. Acceptance criteria: locales array correct;
> `messages/en.json` key-set matches `ru.json` exactly with non-empty values; visiting
> `/en` renders `<html lang="en">` with `/ru` and `/uz` unregressed; LocaleSwitcher
> renders three working options (RU/UZ/EN) navigating correctly between all three locale
> prefixes with anchors preserved; `npm run build` has no type/routing errors; `/en`
> renders all landing sections with no missing-translation-key errors.

Scope test result: this requirement has real user-visible surface (a new `/en` route and
a third `LocaleSwitcher` link) — continuing to the full procedure per WF-02 Step 3, not
routed straight to RELEASE-VALIDATOR.

Design reference: `docs/agents/design/REQ-003.md`. Per that design's §0/§4, this
requirement touches no CSS, no new component, and no theme-specific code (`.lang`/`.lang
a`/`.lang .on` are reused unchanged; the flex-row layout already accommodates a variable
number of children). **Theme-checking does not add coverage here** — no case below has a
theme dimension, matching REQ-001a's spec precedent
(`docs/agents/test-specs/REQ-001a.md`), which established the same for the two-locale
switcher. Cases still specify a mobile and a desktop viewport per
`docs/guides/frontend_developer_guide.md` §4, since the switcher's flex-row layout is the
one thing that changes shape (three children instead of two).

Viewports used (same breakpoints as REQ-001a's spec, confirmed current via
`grep -n "@media" src/app/globals.css` → lines 247 `max-width:980px`, 256
`max-width:620px`):
- **Mobile: 600px** (inside both breakpoints — `.nav-links` hidden)
- **Desktop: 1024px** (outside both breakpoints — full nav visible)

Landing page section order, confirmed by direct read of `src/app/[locale]/page.tsx`:
`Nav`, `Hero`, `Metrics`, `Creed`, `MapSection`, `Events`, `Streams`, `Doors`, `Team`,
`Partners`, `Band`, `Footer` (12 rendered components in this order, plus a non-visual
`ScrollReveal`).

## AC2 — `messages/en.json` key-set matches `messages/ru.json` exactly, all values non-empty

- Route: N/A (data file check, script-based)
- Viewport: N/A
- Theme: N/A
- Steps: from the repo root, run this Node script (exact comparison — key-set equality
  by recursive leaf-path collection, plus an emptiness check):
  ```bash
  node -e "
  function leaves(obj, prefix) {
    let out = [];
    for (const k of Object.keys(obj)) {
      const p = prefix ? prefix + '.' + k : k;
      if (obj[k] && typeof obj[k] === 'object' && !Array.isArray(obj[k])) {
        out = out.concat(leaves(obj[k], p));
      } else {
        out.push(p);
      }
    }
    return out;
  }
  const ru = require('./messages/ru.json');
  const en = require('./messages/en.json');
  const ruKeys = leaves(ru, '').sort();
  const enKeys = leaves(en, '').sort();
  const missing = ruKeys.filter(k => !enKeys.includes(k));
  const extra = enKeys.filter(k => !ruKeys.includes(k));
  function getVal(obj, path) { return path.split('.').reduce((o,p)=>o&&o[p], obj); }
  const empty = enKeys.filter(k => { const v = getVal(en,k); return v === '' || v === null || v === undefined; });
  console.log('ru_count=' + ruKeys.length);
  console.log('en_count=' + enKeys.length);
  console.log('missing=' + JSON.stringify(missing));
  console.log('extra=' + JSON.stringify(extra));
  console.log('empty=' + JSON.stringify(empty));
  "
  ```
- Expected output, exactly:
  - `ru_count=177`
  - `en_count=177`
  - `missing=[]` (no key present in `ru.json` absent from `en.json`)
  - `extra=[]` (no key present in `en.json` absent from `ru.json`)
  - `empty=[]` (no leaf value in `en.json` is `""`, `null`, or `undefined`)

## AC2b — every `en.json` value is the verbatim `ru.json` value except `Metadata.ogLocale`

- Route: N/A (data file check, script-based)
- Viewport: N/A
- Theme: N/A
- Steps: from the repo root, run:
  ```bash
  node -e "
  function leaves(obj, prefix) {
    let out = [];
    for (const k of Object.keys(obj)) {
      const p = prefix ? prefix + '.' + k : k;
      if (obj[k] && typeof obj[k] === 'object' && !Array.isArray(obj[k])) {
        out = out.concat(leaves(obj[k], p));
      } else {
        out.push(p);
      }
    }
    return out;
  }
  const ru = require('./messages/ru.json');
  const en = require('./messages/en.json');
  function getVal(obj, path) { return path.split('.').reduce((o,p)=>o&&o[p], obj); }
  const diffs = leaves(ru,'').filter(k => getVal(ru,k) !== getVal(en,k));
  console.log('diff_keys=' + JSON.stringify(diffs));
  console.log('en_ogLocale=' + JSON.stringify(getVal(en, 'Metadata.ogLocale')));
  console.log('ru_ogLocale=' + JSON.stringify(getVal(ru, 'Metadata.ogLocale')));
  "
  ```
- Expected output, exactly:
  - `diff_keys=["Metadata.ogLocale"]` (this is the ONLY key path whose `en.json` value
    differs from `ru.json` — every other of the 176 remaining leaf values must be
    character-for-character identical to `ru.json`, per the design's verbatim-duplication
    rule)
  - `en_ogLocale="en_US"`
  - `ru_ogLocale="ru_RU"`

## AC4 — LocaleSwitcher renders three working options (RU/UZ/EN), navigates correctly between all three prefixes, anchors preserved

- Route: `/ru`
- Viewport: 600px (mobile)
- Theme: not applicable (see header note)
- Steps:
  1. Load `http://localhost:3000/ru` in a 600px-wide browser viewport.
  2. Confirm the locale switcher (`.lang` element in the header) is visible and not
     `display:none` — only `.nav-links` collapses at this width, `.lang` does not.
  3. Inspect the rendered switcher markup: run
     `curl -s http://localhost:3000/ru | grep -oE '<div class="lang">.{1,300}' | grep -oE '.*</div></div>'`
     (the trailing `</div></div>` closes both the `.lang` div and its parent `.nav-in`
     div immediately after it in the source — this bounds the match to just the switcher
     markup without needing a non-greedy `-P` flag, which this environment's `grep`
     does not support)
- Expected markup, exactly:
  `<div class="lang"><a class="on" href="/ru">RU</a><a hrefLang="uz" href="/uz">UZ</a><a hrefLang="en" href="/en">EN</a></div></div>`
  — three links, in this order (RU, UZ, EN — array order per AC1), `RU` carrying
  `class="on"` (active state) and no `hrefLang` attribute, `UZ` and `EN` each carrying
  `hrefLang` and no `class="on"`. (Verified directly against the running app during spec
  design — this exact string is the real, current output, not an assumption.)
- Continue in the same 600px viewport: click the `EN` control inside `.lang`.
- Expected: browser navigates to `http://localhost:3000/en` (URL bar shows `/en`, no
  other path segments). `document.documentElement.lang === "en"`.

- Route: `/en`
- Viewport: 1024px (desktop)
- Steps:
  1. Load `http://localhost:3000/en` in a 1024px-wide browser viewport.
  2. Run `curl -s http://localhost:3000/en | grep -oE '<div class="lang">.{1,300}' | grep -oE '.*</div></div>'`
- Expected markup, exactly:
  `<div class="lang"><a hrefLang="ru" href="/ru">RU</a><a hrefLang="uz" href="/uz">UZ</a><a class="on" href="/en">EN</a></div></div>`
  (EN now carries `class="on"`, RU and UZ do not — verified directly against the running
  app)
- Continue: click the `RU` control inside `.lang`.
- Expected: browser navigates to `http://localhost:3000/ru`.
  `document.documentElement.lang === "ru"`.

- Route: `/uz`
- Viewport: 1024px (desktop)
- Steps:
  1. Load `http://localhost:3000/uz`.
  2. Click the `EN` control inside `.lang`.
- Expected: browser navigates to `http://localhost:3000/en`.
  `document.documentElement.lang === "en"`. (Covers the `uz → en` direction not exercised
  by the two cases above.)

- Section-anchor preservation check (route: `/ru#events`, viewport: 1024px):
  1. Load `http://localhost:3000/ru#events`.
  2. Inspect the rendered switcher markup: run
     `curl -s http://localhost:3000/ru | grep -oE '<div class="lang">.{1,300}' | grep -oE '.*</div></div>'`
- Expected: same markup as the AC4 `/ru` case above — all three links target bare paths
  (`/ru`, `/uz`, `/en`) with no hash fragment appended by the switcher itself. Since none
  of the three links carry a hash, clicking any option from `/ru#events` (or `/uz#...`,
  `/en#...`) lands on the bare target path — this is the existing, correct behavior for a
  single-page site (established by REQ-001a's spec for the two-locale case) and must
  hold identically now that a third link exists — no link-building code changed, only the
  array it maps over gained a third entry.

## AC6 — `/en` renders all landing sections with no missing-translation-key errors

- Route: `/en`
- Viewport: 600px (mobile) and 1024px (desktop)
- Theme: light (`data-theme="light"`) and dark (`data-theme="dark"`) — this case is a
  full-page content-completeness check, not a token/layout check, so both themes are
  exercised to also catch anything that only reveals missing content when a
  theme-dependent element is visible (per `docs/guides/qa_testing_guide.md` §5's "check
  `data-theme` as specified" step)
- Steps:
  1. With `npm run dev` running, open the browser devtools console, then load
     `http://localhost:3000/en`.
  2. Confirm each of these 12 sections is present and renders visible text content, in
     this order: `Nav` (header with brand + nav links + switcher), `Hero`, `Metrics`,
     `Creed`, `MapSection`, `Events`, `Streams`, `Doors`, `Team`, `Partners`, `Band`,
     `Footer`.
  3. Toggle to `data-theme="dark"` (via the site's own theme control, or by setting the
     attribute in devtools if no control exists) and re-scroll the full page at 1024px.
  4. Repeat steps 1-3 at a 600px viewport.
  5. Inspect the terminal running `npm run dev` (the Node/server console) for any line
     containing `MISSING_MESSAGE`, `next-intl` error text, or a raw dotted key path
     (e.g. `Hero.title`, `Nav.events`) appearing as literal on-page text instead of
     translated copy.
- Expected: all 12 sections render non-empty text in every one of the four
  viewport/theme combinations (600px/light, 600px/dark, 1024px/light, 1024px/dark). No
  section is blank, and no rendered text is a literal namespaced key string (e.g. the
  string `Hero.title` must never appear as visible page text — since REQ-003's
  placeholder values are the Russian source strings duplicated verbatim, every visible
  string on `/en` must read as Russian-language text, not English and not a raw key).
  The dev-server console shows zero `MISSING_MESSAGE` lines and zero next-intl error
  output for the `/en` route across all four checks.
