## Shared setup (run once before AC1–AC8)

1. `cd apps/bot && docker compose up -d` — starts the throwaway Postgres (host port
   `55432`, user/password/db all `bot`).
2. Poll until ready: `docker compose exec postgres pg_isready -U bot` reports
   `accepting connections` (poll every 2s; do not sleep-guess).
3. `export DATABASE_URL=postgres://bot:bot@localhost:55432/bot` (PowerShell:
   `$env:DATABASE_URL = "postgres://bot:bot@localhost:55432/bot"`).
4. From `apps/bot`: `npx drizzle-kit migrate` — applies every migration (REQ-020 adds no
   new migration itself — AC-schema below independently confirms this).
5. Seed fixture rows via `psql "$DATABASE_URL" -c "<statement>"` — exact statements given
   per case. Cases are NOT assumed to share fixture state — run each case's own `DELETE`
   cleanup first.
6. Write the harness scripts under `apps/bot/scratch-verify-req020*.ts` (NOT committed —
   delete all of them at the end of the run). Shared shape:

```ts

import { makeStartHandler, makeChapterCallbackHandler, makeConsentCallbackHandler } from "./src/handlers/start.js";
import { createDbClient } from "./src/db/client.js";

const { db } = createDbClient(process.env.DATABASE_URL!);

const bot = new Bot("000000:DUMMY_TOKEN_NOT_REAL", {
  botInfo: {
    id: 1, is_bot: true, first_name: "Test", username: "test_bot",
    can_join_groups: true, can_read_all_group_messages: false, supports_inline_queries: false,
  },
});

const captured: Array<{ method: string; payload: unknown }> = [];
bot.api.config.use(async (_prev, method, payload) => {
  captured.push({ method, payload });
  return { ok: true, result: true } as never;

bot.command("start", makeStartHandler(db));
bot.callbackQuery(/^chapter:(.+)$/, makeChapterCallbackHandler(db));
bot.callbackQuery(/^consent:agree(?::.+)?$/, makeConsentCallbackHandler(db));
bot.callbackQuery(REGISTER_CALLBACK_PATTERN, makeRegisterCallbackHandler(db));

function messageUpdate(updateId: number, tgId: number, text: string) {
  const isCommand = text.startsWith("/");
  return {
    update_id: updateId,
    message: {
      message_id: updateId, date: Math.floor(Date.now() / 1000),
      chat: { id: tgId, type: "private" as const },
      from: { id: tgId, is_bot: false, first_name: "Test" },
      text,
      ...(isCommand ? { entities: [{ type: "bot_command" as const, offset: 0, length: text.split(" ")[0].length }] } : {}),
    },
  };

async function main() {

  // --- dispatch calls inserted per-case below, in order ---
  console.log(JSON.stringify(captured, null, 2));

main();
```

## AC3 — every `qr_token` is ≥128 bits from a CSPRNG

**Unit-level property already covered — re-run and quote real output:**
```
cd apps/bot && npx vitest run --no-file-parallelism src/domain/registration.test.ts -t "generateQrToken"
```
Expected: exit 0, both existing cases pass (single-token format check; a 1000-token
uniqueness loop).

**This spec's own, independently-designed collision/structure test — 5000 tokens (5x
BACKEND-DEV's sample size) with different assertions than the existing test, not merely a
re-run at a larger N:**

- Write a standalone script (no DB, no bot needed — `generateQrToken` is pure):
  ```ts
  import { generateQrToken } from "./src/domain/registration.js";

  const N = 5000;
  const tokens = new Set<string>();
  const charsSeen = new Set<string>();
  let anyShortRun = false; // true if any token has 8+ identical consecutive hex chars

  for (let i = 0; i < N; i++) {
    const token = generateQrToken();
    if (!/^[0-9a-f]{64}$/.test(token)) {
      throw new Error(`FAIL: token ${i} does not match /^[0-9a-f]{64}$/: ${token}`);
    }
    for (const ch of token) charsSeen.add(ch);
    if (/(.)\1{7,}/.test(token)) anyShortRun = true;
    tokens.add(token);
  }

  console.log(JSON.stringify({
    generated: N,
    uniqueCount: tokens.size,
    distinctHexCharsSeen: charsSeen.size,
    anyPathologicalRun: anyShortRun,
  }, null, 2));
  ```
  Run: `npx tsx apps/bot/scratch-verify-req020-ac3.ts` (from repo root, adjust the import
  path, or run from `apps/bot` with a relative `./src/...` import).
- Expected output: `generated: 5000`, `uniqueCount: 5000` (zero collisions across 5000
  samples — the length/entropy this spec independently checked, not merely trusted from
  the design doc's probability argument), `distinctHexCharsSeen: 16` (all 16 hex digits
  `0-9a-f` actually appear somewhere across the sample — a CSPRNG producing byte values
  from a restricted subrange, e.g. a broken encoder that only ever emits `0-9`, would fail
  this and would not be caught by the existing test's format regex alone, since
  `/^[0-9a-f]{64}$/` accepts an all-digit string too), `anyPathologicalRun: false` (no
  token contains a run of 8 or more identical consecutive hex characters — a cheap,
  deliberately generous, sanity-only check against a badly broken RNG that emits
  long repeated runs; a single failing token here is itself informative even though a
  well-functioning CSPRNG could theoretically produce one by pure chance at a rate far
  below 5000 samples' expected occurrence).
- Pass conditions: `uniqueCount === 5000`, `distinctHexCharsSeen === 16`,
  `anyPathologicalRun === false`, and every one of the 5000 tokens matches
  `/^[0-9a-f]{64}$/` (64 hex chars = 256 bits, clear of S4's ≥128-bit floor). Any
  collision, any non-conforming token, fewer than 16 distinct hex characters observed
  across the sample, or a pathological repeated-run token is a FAIL.
