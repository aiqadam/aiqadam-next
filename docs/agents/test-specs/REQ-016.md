## AC1 — Publish refusal naming each missing/invalid field individually (title,
capacity live; `starts_at` covered by unit test)

Per design §3.1a: `title`/`starts_at`/`ends_at`/`capacity` are `NOT NULL` in the real
schema, so a stored row can never have SQL `NULL` in any of them — AC1's "individually
absent" is satisfied by the design's own "absent-or-invalid" reading (blank-string
`title`, non-positive `capacity`), both of which ARE constructible against the live
schema via a raw fixture `INSERT` that bypasses `createEvent`'s own validation. `starts_at
= NULL` is genuinely **not** constructible against this schema (Postgres itself rejects a
literal `NULL` insert into a `NOT NULL` column) — this sub-case is verified instead by the
already-existing unit test in `apps/bot/src/domain/event.test.ts`, not by a live dispatch.

### AC1a — blank `title`

- Fixture:
  ```sql

  INSERT INTO chapters (id, code, name, timezone, default_lang, active)
    VALUES ('90000001-0000-0000-0000-000000000000', 'ac1', 'AC1 Chapter', 'Asia/Tashkent', 'ru', true);
  INSERT INTO users (id, tg_id, role, chapter_id)
    VALUES ('90000001-0000-0000-0000-00000000000f', 900000001, 'organizer', '90000001-0000-0000-0000-000000000000');
  INSERT INTO events (id, chapter_id, title, description, format, venue_id, starts_at, ends_at, capacity, status)
    VALUES ('90000001-0000-0000-0000-0000000000a1', '90000001-0000-0000-0000-000000000000',
            '   ', 'valid description', 'meetup', NULL,
            now() + interval '10 days', now() + interval '10 days 2 hours', 50, 'draft');
  ```
  Note: `venue_id` is deliberately `NULL` here too (every event needs one per AC2), but
  this case only asserts on the `title` name appearing — AC1a's pass condition below
  checks `title` is present in the refusal, not that it is the ONLY name (venue is also
  legitimately missing on this row; `findMissingPublishFields` is list-driven and returns
  every failing key, per design §3.1 — see AC1's combined pass condition 3).
- Dispatch:

  `${event.publishRefusedMissingFields} title, venue` (ru catalog:

  exact prefix by reading `apps/bot/src/i18n/ru.ts`'s `event.publishRefusedMissingFields`
  value at run time; order is table order from design §3.1: title, starts_at, ends_at,
  capacity, venue — since starts_at/ends_at/capacity are valid on this row, the two names
  present are `title` then `venue`, in that order).
- Read-back: `SELECT status FROM events WHERE id = '90000001-0000-0000-0000-0000000000a1';`
  → still `'draft'` (no transition occurred).

### AC1c — `starts_at` (untestable against the live schema; covered by unit test)

`starts_at` is `timestamp NOT NULL` in `apps/bot/src/db/schema.ts` — no raw `INSERT` can
produce a stored row with `starts_at IS NULL`, so this sub-case cannot be constructed live
against the real database, per design §3.1a/§11 open question 2's own documented gap.

- Command: `cd apps/bot && npx vitest run src/domain/event.test.ts -t "findMissingPublishFields"`
- Expected: exit 0, and the printed test list includes, passing, the case
  `"names 'starts_at' when null"` (currently `apps/bot/src/domain/event.test.ts` lines
  143–145: `expect(findMissingPublishFields(baseEvent({ startsAt: null }))).toEqual(["starts_at"]);`).
  This is a real, already-authored unit test exercising the exact predicate
  `findMissingPublishFields` that `/event_publish` calls — it proves the mechanism names

- Pass condition: the named test exists, runs, and passes. If it is missing or renamed,
  this sub-case FAILs — a "trust the design doc" pass without confirming the test actually
  exists and executes is not acceptable per core-directives.md's No Speculation rule.

**AC1 combined pass conditions:**
1. AC1a's refusal names `title` (and also `venue`, in that order, per the list-driven
   mechanism) — a refusal that omits `title` or names it in the wrong position (e.g.
   `venue, title`) is a FAIL.
2. AC1b's refusal names `capacity` and ONLY `capacity`.
3. Neither AC1a's nor AC1b's event transitions out of `draft`.
4. AC1c's named unit test exists and passes (quote the real vitest output).
