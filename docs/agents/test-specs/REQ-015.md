# REQ-015 — Verification spec: Venue CRUD for organizers, chapter-scoped

**Scope test:** Step 2's `artifacts_out` (`apps/bot/src/domain/{venueAuthorization,
venue,auditLog}.ts`, `apps/bot/src/handlers/venue.ts`, new `apps/bot/src/i18n/
{types,ru,en}.ts` `venue.*` keys, registration in `apps/bot/src/index.ts`) is real
user-visible/behavioral surface — a live Telegram bot process creates, edits and deletes
real `venues` rows and writes real `audit_log` rows depending on who calls which command
against which chapter/venue. Full Steps 3b/4 apply, not a docs-only skip.

**Harness note (read before running any case):** this reuses REQ-013/REQ-014's
established grammY-dispatch method exactly — a real `grammy.Bot` built with a dummy
token + manually-supplied `botInfo`, `bot.api.config.use()` intercepting outbound calls,
`bot.handleUpdate()` dispatching synthetic `Update` objects through the real
command matcher, against the real fixture Postgres from `apps/bot/docker-compose.yml`.
Not committed as reusable infrastructure — the harness script below is written, run,
then deleted at the end of the run (per the standing recommendation in
`docs/agents/test-specs/REQ-013.md`).

   against the same scratch DB without collision).
6. Write the harness script to `apps/bot/scratch-verify-req015.ts` (NOT committed —

**Harness script (`apps/bot/scratch-verify-req015.ts`), exact content:**

```ts
import { Bot } from "grammy";
import {
  makeVenueNewHandler,
  makeVenueEditHandler,
  makeVenueDeleteHandler,
  makeVenuesListHandler,
} from "./src/handlers/venue.js";
import { createDbClient } from "./src/db/client.js";

const { db } = createDbClient(process.env.DATABASE_URL!);

const bot = new Bot("000000:DUMMY_TOKEN_NOT_REAL", {
  botInfo: {
    id: 1,
    is_bot: true,
    first_name: "Test",
    username: "test_bot",
    can_join_groups: true,
    can_read_all_group_messages: false,
    supports_inline_queries: false,
  },
});

const captured: Array<{ method: string; payload: unknown }> = [];
bot.api.config.use(async (_prev, method, payload) => {
  captured.push({ method, payload });
  return { ok: true, result: true } as never;
});

bot.command("venue_new", makeVenueNewHandler(db));
bot.command("venue_edit", makeVenueEditHandler(db));
bot.command("venue_delete", makeVenueDeleteHandler(db));
bot.command("venues", makeVenuesListHandler(db));

function messageUpdate(updateId: number, tgId: number, text: string) {
  const firstLine = text.split("\n")[0];
  return {
    update_id: updateId,
    message: {
      message_id: updateId,
      date: Math.floor(Date.now() / 1000),
      chat: { id: tgId, type: "private" as const },
      from: { id: tgId, is_bot: false, first_name: "Test" },
      text,
      entities: [{ type: "bot_command" as const, offset: 0, length: firstLine.split(" ")[0].length }],
    },
  };
}

async function main() {
  await bot.init();
  // --- dispatch calls inserted per-case below, in order ---
  console.log(JSON.stringify(captured, null, 2));
  process.exit(0);
}

main();
```

## ISS-0008 regression case — past-event-only deletion hits the RESTRICT FK (documented
current behavior, not a new requirement)

**This case does not test an acceptance criterion.** No REQ-015 AC governs
past-event-only deletion (design §9.2 flags this explicitly as an open question
deferred to REQ-016/DATA-DESIGNER, and `docs/issues/ISS-0008.yaml` records it as a
known, already-reproduced MINOR issue: the `restrict` FK on `events.venue_id` rejects
a `DELETE` on a venue referenced by ANY event, past or future, producing a raw
FK-violation error instead of the application's friendly `deleteRefusedFutureEvent`
message). This case exists to give TEST-RUNNER a precise, mechanical reproduction of
that EXACT documented behavior — proving the current code still behaves the way
ISS-0008 describes (a regression here would mean either (a) the FK silently stopped
being enforced, which would be a data-integrity regression, or (b) the raw error
started leaking something new, e.g. via an added `bot.catch()` that echoes it to the
user) — not asking for or grading a fix.

