- Route: N/A (filesystem check)

- Theme: N/A
- Steps:
  1. From the repo root, run:
     ```bash
     ls apps/web/package.json apps/web/next.config.ts apps/web/tsconfig.json apps/web/eslint.config.mjs apps/web/next-env.d.ts
     ```

## AC3 — Post-move runtime: all four locales serve correctly and /health returns 200

> "`npm run build && npm run start` from the repo root serves all four locales: /ru,
> /uz, /en and /kk each render with the matching `<html lang>` value and no
> missing-translation-key errors, and /health returns HTTP 200 — matching the
> verification REQ-005 used, re-run after the move."

- Route: `/ru`, `/uz`, `/en`, `/kk`, `/health`
- Viewport: N/A (server-response check, not a layout check)
- Theme: N/A
- Steps:
  1. From the repo root, run `npm run build`, confirm exit code `0` (may reuse AC2
     step 2's build if already run and passing in the same session; otherwise re-run).
  2. From the repo root, run `npm run start` (starts the server on the app's configured
     port — confirm the port from the terminal output, e.g. `http://localhost:3000`).
  3. With the server running, request each locale route and inspect the HTML response,
     e.g.:
     ```bash
     curl -s http://localhost:3000/ru | grep -o '<html[^>]*lang="[^"]*"'
     curl -s http://localhost:3000/uz | grep -o '<html[^>]*lang="[^"]*"'
     curl -s http://localhost:3000/en | grep -o '<html[^>]*lang="[^"]*"'
     curl -s http://localhost:3000/kk | grep -o '<html[^>]*lang="[^"]*"'
     ```
  4. For each of the four responses in step 3, search the full HTML body for any
     visible next-intl fallback/error marker: grep for the literal substrings
     `MISSING_MESSAGE` and `IntlError` (next-intl's fallback text/error identifiers).
  5. Request the health route:
     ```bash
     curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/health
     ```
  6. Stop the server (Ctrl+C or kill the process) once steps 3-5 are recorded.
- Expected:
  - Step 3: `/ru` response's `<html>` tag has `lang="ru"`; `/uz` has `lang="uz"`;
    `/en` has `lang="en"`; `/kk` has `lang="kk"` — each matching its own route segment,
    no cross-locale mismatch.
  - Step 4: zero matches for `MISSING_MESSAGE` or `IntlError` in any of the four
    responses.
  - Step 5: output is exactly `200`.

## AC4 — apps/web/messages/ has exactly 4 catalogs with identical key sets

> "apps/web/messages/ contains exactly the four catalogs ru.json, uz.json, en.json,
> kk.json with identical key sets (re-verified by the same key-set diff script REQ-005's
> acceptance criteria used), proving the move lost no catalog content."

- Route: N/A (data file check, script-based)
- Viewport: N/A
- Theme: N/A
- Steps:
  1. From the repo root, run `ls apps/web/messages/` and confirm the file list.
  2. From the repo root, run this Node script (same key-set diff method used in
     `docs/agents/test-specs/REQ-005.md` AC2, extended to all four catalogs against the
     `ru.json` baseline):
     ```bash
     node -e "
     function leaves(obj, prefix) {
       let out = [];
       for (const k of Object.keys(obj)) {
         const p = prefix ? prefix + '.' + k : k;
         if (obj[k] && typeof obj[k] === 'object' && !Array.isArray(obj[k])) {
           out = out.concat(leaves(obj[k], p));
         } else {
           out.push(p);
         }
       }
       return out;
     }
     const ru = require('./apps/web/messages/ru.json');
     const uz = require('./apps/web/messages/uz.json');
     const en = require('./apps/web/messages/en.json');
     const kk = require('./apps/web/messages/kk.json');
     const ruKeys = leaves(ru, '').sort();
     console.log('ru_count=' + ruKeys.length);
     for (const [name, obj] of [['uz', uz], ['en', en], ['kk', kk]]) {
       const keys = leaves(obj, '').sort();
       const missing = ruKeys.filter(k => !keys.includes(k));
       const extra = keys.filter(k => !ruKeys.includes(k));
       console.log(name + '_count=' + keys.length + ' missing=' + JSON.stringify(missing) + ' extra=' + JSON.stringify(extra));
     }
     "
     ```
- Expected:
  - Step 1: `ls` lists exactly 4 entries — `en.json`, `kk.json`, `ru.json`, `uz.json` —
    no more, no fewer.
  - Step 2 output exactly:
    ```
    ru_count=177
    uz_count=177 missing=[] extra=[]
    en_count=177 missing=[] extra=[]
    kk_count=177 missing=[] extra=[]
    ```
    Any nonzero `missing`/`extra` array, or any count other than `177`, is a FAIL.

> "`git log --follow apps/web/src/i18n/routing.ts` shows the pre-migration commit
> history, proving `git mv` was used rather than a delete-and-recreate."

- Route: N/A (git history check)
- Viewport: N/A
- Theme: N/A
- Steps: from the repo root, run:
  ```bash
  git log --oneline --follow -- apps/web/src/i18n/routing.ts
  ```
- Expected: the output contains at least 4 commits, including all of the following
  (identify by message substring; exact hashes will differ per checkout):
  1. A commit describing the move into `apps/web` (this run's own commit).
  2. `feat: add Kazakh (kk) locale to i18n routing and translate all landing copy [WF02-REQ005-REQ006]`
  3. `feat: add English (en) locale to i18n routing and translate all landing copy [WF02-REQ003-REQ004]`

  beneath it), that is a FAIL — it means the move was recorded as a new file (delete +
  add) rather than a tracked rename, even if AC1's existence check passed.
